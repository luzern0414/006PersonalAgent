# 06 · 实现说明（v0.1 已落地版本）

> 本文描述**当前代码的实际实现**。01~05 是设计阶段文档，与实现不同之处以本文为准。

## 1. 与设计方案的差异

| 设计（03-技术方案） | 实际实现 | 原因 |
|---|---|---|
| Tauri 2（Rust）壳 | **Electron 44** | 本机没有 Rust / MSVC 工具链，安装 VS Build Tools 需要数 GB 并且要管理员权限。Electron 的 `setIgnoreMouseEvents(..., {forward:true})` 也能很方便地实现透明区域点击穿透 |
| Python FastAPI Sidecar | **单进程 Node**（核心逻辑跑在 Electron 主进程） | 少一个常驻进程，可省下约 60~100MB 内存；不需要再打包 Python |
| SQLite + LanceDB | **JSON 文件存储 + 自研 BM25 检索**（可选向量检索） | 不用原生模块，免编译；个人数据量用 JSON 足够；知识库目录可整体搬家 |
| YAML 配置 | `config/settings.json` + 设置界面 | 界面读写方便；密钥用 Windows DPAPI 加密保存 |

## 3. 架构

三类进程，各管各的：

```
┌──────────── 主进程 main.js（只管窗口与系统交互）────────────┐
│ 宠物/面板窗口、托盘、快捷键、系统通知、剪贴板、文件对话框          │
│ 设置读写与 DPAPI 加解密、命中测试（光标轮询）、提醒投递             │
│ core-client.js：启动 / 调用 / 自动重启后台进程                     │
└───────┬──────────────────────────────────────┬────────────┘
        │ IPC（preload 白名单）                  │ MessagePort（call / result / emit …）
┌───────┴────────────┐              ┌──────────┴─────────────────────────────┐
│ 宠物窗口 / 面板窗口  │              │ 后台业务进程 worker/core-host.js           │
│ （渲染进程）         │              │ （Electron utilityProcess）                 │
└────────────────────┘              │ core/services 待办 日程 提醒 文档 记忆 日报   │
                                    │ core/agent + tools（24 个工具）             │
                                    │ core/llm 模型 + LangSmith、core/weather     │
                                    │ core/scheduler 主动提醒、core/kb 解析 OCR 检索 │
                                    │ core/store JSON 存储                       │
                                    └──────────────────────────────────────────┘
```

- **为什么拆进程**：运行日志显示，主进程曾多次被整体阻塞 30～60 秒；阻塞期间没有任何 JS 操作在执行，堆内存也只有 8～14MB，说明主线程卡在原生调用上。有两次紧跟在提醒投递之后，一次发生在天气联网时（请求的 10 秒超时直到 60 秒后事件循环恢复才触发）。原先所有业务都和窗口挤在同一个主进程里：联网、模型调用、PDF 解析、同步读写 JSON、调度器……任何一处卡住，宠物和面板都会跟着无响应。现在业务全部在后台进程运行，主进程只剩窗口相关的轻量工作
- **握手与设置**：后台加载后发 `hello` → 主进程下发设置和（解密后、只在内存里的）密钥 → 后台初始化业务核心并回 `ready`。设置只由主进程写入，后台不读写 `settings.json`
- **环境信息**：主进程每 2 秒把系统空闲时长和全屏状态推给后台调度器；锁屏、解锁、休眠唤醒事件也会转发过去
- **对话**：在后台运行，流式输出和「需要确认」的请求经主进程转发给面板
- **容错**：后台进程退出后会按 1s、2s、4s……（最多 30s）的间隔自动重启，其间发起的调用会等待新进程就绪；退出程序时先让后台把数据写盘、上传 trace，再结束
- **测试替身**：设置环境变量 `PA_CORE_FIXTURE` 指向一个模块，后台会在初始化前加载它，用来替换核心模块的实现（只在 `scripts/verify-panel.js` 这类隔离测试中使用）
- `core/` 仍然不依赖 Electron，所以 `scripts/verify-langsmith.js` 能直接用 Node 跑出和桌面端完全相同的 Agent 链路

## 4. 功能清单（已实现）

### 桌宠
- 透明、置顶、不抢焦点、不占任务栏；透明区域鼠标穿透
- 拖动（在主进程跟随光标，鼠标在窗口外松开也能结束拖动）、松手贴边吸附、位置记忆，多显示器下自动校正位置
- 单击打开或收起面板；右键菜单：聊天、喝水打卡、起立打卡、番茄专注、勿扰 1 小时、收藏剪贴板、隐藏、设置、退出
- 透明区域穿透**不使用** `setIgnoreMouseEvents(..., { forward: true })`：在 Windows 上它会安装系统级低层鼠标钩子，全系统每次鼠标移动都要经过主线程，主线程稍忙就会让整个桌面的鼠标卡顿。现在完全靠主进程每 90ms 轮询一次光标位置来判断是否命中宠物
- 状态动画：待机呼吸、眨眼、睡觉、思考、说话、提醒、开心、被拖动、吃文件、喝水、伸懒腰；专注时戴耳机，下雨天撑伞
- 眼睛跟随鼠标；离开电脑 5 分钟会睡着，回来时醒来打招呼
- 悬停显示信息条：距下班时间、下一个日程、任务进度、喝水杯数
- **投喂**：把文件、文件夹、网页链接或文字拖到宠物身上，自动收进知识库

### 面板 = 桌面组件（5 个标签：今日 / 对话 / 日程待办 / 知识库 / 设置）
- **打开与收起**：没有标题栏按钮，点团子就能打开或收起；如果面板被其他窗口挡住，点团子会先把它提到最前
- **固定在桌面**：不占任务栏；切到别的程序时，面板会沉到所有程序窗口之后、桌面之上（通过 Win32 `SetWindowPos(HWND_BOTTOM)` 实现，已用 z 序验证），用起来像桌面小组件；拖到哪里、调成多大都会记住
- **今日（首页）**：从上到下是天气 → 安排 → 知识库，铺满整页、可以滚动，没有问候卡
  - **天气**（紧凑卡片，约 150px 高）：城市固定为深圳。一行显示图标、温度、天气 · 体感 · 湿度、最低/最高温和日出日落，下面是可横向滚动的逐小时预报（降雨概率 ≥ 30% 时标出）。背景是随「天气类型 × 白天/夜晚」变化的天空渐变；按数据只给最重要的一条提示（降雨 ≥ 50%、明天升降温 ≥ 5°、紫外线 ≥ 8）
  - **安排**：日程、提醒、待办按时间排列，可以勾选完成、删除；工作日下班前和下班后会出现「写日报」，点了会跳到对话并自动发出「帮我写今天的工作日报」
  - **知识库**：搜索框，加上最近收录的 5 篇资料，点开就是原文
  - **随时间切换视角**：
    | 时段 | 天气 | 安排 |
    |---|---|---|
    | 上班前 / 工作中 | 今天（当前温度 + 接下来 24 小时） | 今天全部 |
    | 工作日距下班不到 `home.tomorrowLeadMin` 分钟（默认 60），或已下班 | 明天（最低~最高温 + 明天 6–23 点） | 今天还剩的 + 明天全部 |
    | 休息日 `home.restDayTomorrowAt`（默认 18:00）之后 | 明天 | 同上 |

    阈值都取自设置，不写死；首页每分钟自动刷新，正在输入或有弹窗时跳过
- **对话**：一个连续的对话，打开就显示全部历史（按日期分隔）；输入框没有提示文字，**草稿持久化**（切页面、面板被释放后重建都不会丢）；请求失败或被停止时也会留一条说明，历史里不会出现「只有提问、没有回答」
- **日程待办**（只读 + 勾选 / 删除）：
  - **周历**：默认只显示本周，可「展开月历」；圆点表示这天有安排——橙色是未完成待办，灰色是待办全部完成，蓝色是日程，紫色是提醒
  - **当天安排**：日程、提醒、待办按时间排在一起；默认是今天，点日历上的某天切换
  - **全部待办**：不受日期范围限制，可筛选全部 / 未完成 / 已完成
  - **完成状态**：待办勾选后划线保留，不会消失；提醒勾选或已过时间同样划线保留（重复提醒只划掉当天这一次）；过去的日程变淡
- **新增和修改全部通过对话完成**：界面上不再有待办、提醒、日程的输入框和编辑弹窗，知识库也不再有「添加网址 / 文本 / 新建文档」。直接对小管家说，例如「明天下午三点和产品对需求」「把周会提醒改到 10 点半」「收藏这个链接 https://…」
- **知识库**：拖入文件或点击选择、收藏剪贴板截图；支持搜索；「文档」页只读查看
- **设置**（改了就自动保存）：昵称（默认「老大」）；AI 服务（地址、Key、模型、测试）；**提醒设置**（喝水 / 起立 / 护眼频率、上下班时间、下班预告、日程提前、喝水目标、稍后提醒、工作日等）；保存位置（知识库、文档）；群机器人管理
- 开机自启、勿扰、退出在托盘或宠物右键菜单里

### 界面设计
参考了 [Fluent Design](https://learn.microsoft.com/en-us/windows/uwp/design/fluent-design-system) 的分层与材质思路（安静的画布 + 浮起的内容卡片，见 [Acrylic](https://learn.microsoft.com/windows/uwp/style/acrylic)），以及 [Mercury Weather](https://www.macstories.net/?p=72671)、[Drizzle](https://apps.apple.com/app/id6752252972)、[Weathergraph](https://apps.apple.com/app/id1501958576) 这类天气应用「渐变天空 + 横向逐小时条」的布局：
- 顶部标签栏同时是拖动区：未选中的标签只显示图标，选中的显示文字；没有标题栏和窗口按钮
- 图标统一为内联 SVG：界面用 1.8px 线性图标（风格参考 Lucide），天气用彩色图标；不再用 emoji，也不发网络请求
- 色彩：暖灰画布（深色模式为近黑），卡片白底细边框加极淡阴影；只有一个强调色（珊瑚橙，和团子呼应），蓝色和紫色分别标记日程和提醒
- 字体：Segoe UI Variable（温度用 Display 细体），数字用等宽数字对齐
- 完成状态：勾选框变绿，标题加删除线、变淡；过去的日程整体变淡

### 待办的数据模型
- 每个待办都属于某一天：优先用 `planDate`，其次用截止时间 `due` 所在那天，都没有就用创建那天
- 每天第一次 tick 时，把之前没完成的待办顺延到今天（记录 `carried` 天数）
- 一次性提醒勾选后会关闭；重复提醒勾选只是把那一天写进 `doneDates`，调度器计算下次触发时会跳过这些日子

### 图片 OCR
| 模式（`kb.ocr`） | 说明 |
|---|---|
| `auto`（默认） | 优先用视觉模型（默认就是对话模型 gpt-6-luna，也可以在 `llm.visionModel` 单独指定），失败时改用本地引擎 |
| `vision` | 只用视觉模型：质量最好，能识别表格、手写，没有文字的图片会给出描述；图片会发送到模型服务 |
| `local` | 只用本地 tesseract.js（WASM，中英文模型随依赖附带，离线、不上传）；识别期间约多占 100MB，空闲 60 秒后自动释放 |
| `off` | 关闭 |

覆盖范围：拖入或选择的图片（png/jpg/webp/gif/bmp/tiff）；**扫描版 PDF**（某页文字层少于 20 字时，提取该页的图片做 OCR）；**剪贴板截图**（右键菜单「收藏剪贴板」或知识库页的截图按钮）。大图会先用 Electron nativeImage 缩到 2000px 以内再送视觉模型。视觉 OCR 在 LangSmith 中记为 `ocr_vision`。

实测（同一张中文会议纪要图）：视觉模型 1.5~2.7 秒，结果完全正确；本地引擎 0.1~0.4 秒，结果正确（自动去掉中文字之间多余的空格）。

## 5. 配置

### 5.1 API Key 文件
默认路径为 `config/apikey.txt`（可在 `settings.json` 的 `llm.apiKeyFile` 改成任意路径）。支持以下几种写法：

```
url：https://xxx/v1
key：sk-xxxx
langsmith：lsv2_xxxx
```

也支持「第一行地址、第二行 Key」的无标签写法和 JSON 写法（见 `config/apikey.example.txt`）。设置界面里填写的地址或 Key 会覆盖文件中的值，其中 Key 用 Windows DPAPI 加密后再存进 `settings.json`。

### 5.2 settings.json
首次运行时自动生成 `config/settings.json`，所有选项都能在界面里修改。路径既可以写相对路径（相对项目根目录），也可以写绝对路径，并支持 `%APPDATA%` 这类环境变量。

### 5.3 提示词
- `config/prompts/system.md`：Agent 人设与行为准则。支持变量 `{{user.nickname}}`、`{{today_snapshot}}`、`{{memories}}`
- `config/prompts/daily_report.md`：日报模板

## 6. LangSmith 全链路

界面上不显示追踪标记，后台每轮对话都会生成一条 trace：

```
[chain] PersonalAgent            ← 一轮对话（带 conversation_id、model 元数据）
  ├─ [llm]  ChatOpenAI           ← 显式 traceable(run_type=llm)，含 messages/tool_calls/token 用量
  ├─ [tool] add_task             ← 每个工具调用：入参 + 返回值
  ├─ [tool] search_knowledge
  ├─ [llm]  ChatOpenAI
  └─ ...
```

另外，日报生成会记为 `daily_report`，图片识别会记为 `ocr_vision`，设置页的「测试连接」会记为 `connection_test`。

**验证方法**：在 `apps/desktop` 目录下执行

```
npm run verify:langsmith
```

脚本会在临时目录里跑一轮真实对话（触发新建任务、知识库检索、查任务三个工具），再从 LangSmith API 拉回这条 trace 的树形结构并打印出来。实测结果（模型 gpt-6-luna）：

```
- [chain] PersonalAgent  12482ms tokens=8870
  - [llm] ChatOpenAI  1977ms tokens=1608
  - [tool] list_tasks  0ms
  - [llm] ChatOpenAI  2429ms tokens=1644
  - [tool] add_task  0ms
  - [llm] ChatOpenAI  2073ms tokens=1755
  - [tool] list_tasks  0ms
  ...
```

> 实现细节：一开始用 `wrapOpenAI` 追踪流式调用，偶尔会丢掉最后一个 llm 节点，因为流式 run 是异步收尾的。现在改为用 `traceable(run_type:'llm')` 显式包裹整个流式读取过程，函数返回时节点就结束，多次验证都没有再丢节点。

## 7. 性能

| 场景 | 实测 |
|---|---|
| 常驻（只有宠物） | **约 250MB**：主进程 73 + 后台业务进程 61 + 运行监测进程 53 + 宠物渲染 29 + GPU 15 + 网络服务 11 + 崩溃收集 9（拆分前约 126MB；后台进程用来隔离卡顿，运行监测进程用于诊断，可在确认稳定后合并或关闭） |
| 面板打开 + 对话 + 知识库已加载 | 约 194MB |
| 待机 CPU | 约单核的 1.4%（20 秒采样） |

采取的措施：
1. 默认关闭 GPU 加速（`performance.disableGpu`），透明小窗用软件合成就够了
2. 关闭用不到的 Chromium 特性（备用渲染进程、媒体会话等），并限制 V8 堆上限
3. 面板窗口**懒创建**，收起 N 分钟后销毁（默认 3 分钟），同时卸载知识库索引并主动 GC
4. `openai`、`langsmith`、`unpdf`、`mammoth`、`koffi` 都是**用到时才加载**
5. 待机动画用 `steps()` 降低重绘频率（约 5fps）；窗口隐藏时 Chromium 会自动节流
6. 光标命中测试每 90ms 一次，只在状态变化时才调用 `setIgnoreMouseEvents`；眼睛跟随按 8px 网格去抖
7. JSON 存储做防抖合并写入；对话只带最近 N 轮历史，减少 token 消耗

### 卡顿修复后的实测（2026-10-12）
- 90 秒混合压测（切标签、提醒气泡、光标反复进出宠物和气泡、面板失焦沉底、点宠物开关面板）：主进程 IPC 往返 p95 = 2ms，最大 2ms，日志中没有任何「事件循环阻塞」
- 一轮真实对话（模型约 13 秒）期间持续探测：主进程响应最慢 1ms
- 强杀后台进程：1 秒内自动重启，之后接口照常可用
- `scripts/verify-panel.js`、`scripts/verify-runtime.js` 全部通过

## 9. 已知限制与后续计划

- 按需求不接入外部日历（Outlook / Google / 飞书等），日程只存在本地
- 按「显示桌面」（Win+D）时，面板会和其他窗口一起被隐藏；点团子可以重新打开
