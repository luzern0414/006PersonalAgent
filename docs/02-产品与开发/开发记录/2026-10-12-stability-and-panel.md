# 小管家稳定性与面板调整 Implementation Plan

> For agentic workers: use independent tasks with explicit file ownership and review results before integration.

**Goal:** 排查 Windows 整窗未响应，并完成用户指定的紧凑天气、周/月日程、统一安排与对话草稿持久化。

**Architecture:** 保持现有 Electron 主进程、IPC 和轻量 DOM 界面。按主进程稳定性、日程展示、对话状态三个边界分工；不改变现有数据格式及 Luna 网关配置。

**Tech Stack:** Electron 44、Node.js、原生 JavaScript/CSS、node:test。

## Design

- 沿用当前颜色、字体与圆角；天气缩小内边距、温度字号和小时预报间距。
- 日程默认周一至周日的一行周历，按钮展开为月历；按天列表合并待办、提醒、日程。
- 同页提供“全部待办”，包含范围外、未完成和已完成待办，并支持现有编辑、完成、删除操作。
- 对话输入无占位说明，草稿在切页、窗口释放及重启后恢复；发送成功后清空，发送失败保留可恢复草稿。
- 稳定性必须区分实测根因与潜在风险：进程、Windows 挂起记录、同步原生调用耗时、主线程事件循环延迟。

## Tasks

- [x] 主进程：收集挂起记录并测量原生窗口 API；可复现后以最小修复处理，增加必要的挂起/崩溃日志。
- [x] 日程：更新 plan.js 与必要的样式，验证周/月切换、跨月周、统一条目及全部待办操作。
- [x] 对话：更新 chat.js 草稿持久化及切页时的发送状态恢复，验证未发送文本与发送失败。
- [x] 天气：缩小天气高度，目视检查 420px 面板。
