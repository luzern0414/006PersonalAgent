# 02 · 开源项目调研与可借鉴点

> 调研日期：2026-10-10。项目活跃度和许可证会变化，**引用代码前请到仓库确认 LICENSE**（特别是 GPL 类许可证会传染）。

## 1. 结论先行

- **没有一个现成项目能直接满足"桌宠 + 工作助理 + 知识库 + 提醒/日程/发送"全部需求**。现有项目大致分成三类：
  1. **桌宠类**（形态好，但几乎没有工作能力）
  2. **AI 伴侣 / VTuber 类**（有 LLM + 角色，但偏陪聊娱乐）
  3. **桌面 AI 客户端 / 知识库类**（能力强，但是普通窗口应用，不"常驻桌面"）
- 本项目的定位正好是三者的交集，因此采用 **"自研外壳 + 借鉴形态 + 复用成熟库"** 的路线：
  - 形态与窗口技巧借鉴 **BongoCat（Tauri）**、**VPet**、**Open-LLM-VTuber 桌宠模式**；
  - 对话 / 多模型 / MCP 交互借鉴 **Cherry Studio**、**LobeChat**、**TouchAI**；
  - 知识库流水线借鉴 **AnythingLLM**、**RAGFlow**，文档解析直接用 **MarkItDown / Docling**。

## 7. 借鉴清单（落到本项目）

1. **窗口层**：照搬 BongoCat 的 Tauri 透明窗口 + 穿透做法；三窗口拆分（宠物 / 面板 / 快速输入）。
2. **动画层**：采用 VPet 的"开始-循环-结束"三段式动画 + 状态机，皮肤包配置化（`assets/pets/<name>/pet.json`）。
3. **架构层**：采用 Open-LLM-VTuber 的"Python 负责 AI、前端只负责表现"的前后端分离。
4. **模型层**：参考 Cherry Studio 的 Provider 抽象，一份配置兼容 Claude、OpenAI 兼容接口与 Ollama。
5. **知识库**：参考 AnythingLLM 的流水线，解析层直接用 MarkItDown，复杂 PDF 用 Docling 增强。
6. **扩展层**：MCP 双向——既是 MCP 客户端（接外部工具），也把"待办/日程/知识库"暴露成 MCP Server（参考 PinedIn），让 Claude Code 等工具也能读写你的待办。
7. **记忆**：参考 mem0 / AIRI，区分"会话记忆"和"用户画像记忆"。
